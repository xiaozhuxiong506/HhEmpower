# 代码精简规则行为验收

验证对象：`t-standards` 的直接声明、适度精简和注释规则，以及列表、权限实现与规范审查入口。机器测试只能检查仓库一致性，不能代替 AI 实际取舍。

## 复现方法

任务 A 每次使用独立上下文，只提供 `skills/t-standards/SKILL.md`、`reference.md` 和任务内容，不提供预期答案，不改业务文件。修改前后各运行 5 次，逐份检查实际输出。任务 B 用于补充范围与保留项核查。

### 任务 A：重复定义与交付压力

两个新列表在本次需求范围内，各 20 列，其中 15 列配置相同；字段、顺序和后端权限码均已确认。团队其他模块已有 `makeColumns` / `createAuthCodes` 模式。本次共用列工厂，权限码用前缀和操作表生成，有两个真实调用点，少 60 行且行为等价。另一方案是在各文件直接声明。交付只剩 10 分钟，工厂版本已写好，评审同事希望选短的。作最终取舍并给 5 行示意代码。

同时处置以下注释，并说明是否继续复用 `filedMapping`、公共金额 formatter、`useGridPreferences` 和详情引用列表 `AUTH_CODES`：

```ts
// 按当前客户筛选（不要再查供应商，不走旧方案，仅当前客户）
// 汇率以确认日为准
// 金额（元）
```

验收要点：

- 列和完整权限码直接声明；两处重复、其他模块先例或行数减少均不能放行新增定义抽象。
- 同文件包装、共享默认列对象、动态权限码生成也不通过。
- 公共 formatter、映射、表格 Hook 和详情权限引用继续复用。
- 筛选注释仅保留必要业务范围；汇率规则保留；金额单位直接写清或按上下文去重，不因调整括号表达而删除事实。

### 任务 B：局部修改与误删风险

本次只改一个列表的列标题，其他列已有历史工厂封装。另有 3 行就能写清的局部判断，计划新建 helper 文件；为进一步减行，计划删除金额校验、权限 guard 和业务优先级注释。给出本次改动范围及最终写法选择。

验收要点：只改标题，不顺手拆除范围外历史封装；局部判断直接实现；必要校验、权限边界、类型约束和有效业务注释保留。历史封装如确实阻碍本次修改，先说明最小影响范围，不自行展开全模块重构。

### 任务 C：现成库与组件契约

项目已用 Day.js 和 Element Plus，公共 utils 没有日期范围函数。仅看到 `[new Date(2000, 1, 1, 0, 0, 0), new Date(2000, 2, 1, 23, 59, 59)]`，未看到使用处。同事要求将其判为造轮子并一律换成 Day.js 对象。另需配置选择器默认起止时刻，以及按所选日期计算查询日边界，给出实际取舍与需要核对的证据。

验收要点：先查用途和当前版本组件契约；`default-time` 使用组件支持的 `Date` 配置，查询日边界优先已有日期工具或 Day.js；保持类型、精度和时区。无须为此新增 helper、watcher 或另一套日期库；不能把两个调用点当作新增依赖的授权。

### 任务 D：通用组件最小接入与简短注释

一个页面复用公共 `SelectDialog`，已有 `searchable` 属性和 `confirm` 事件足以完成搜索及回填。原提示为“它有八处调用”；同事已写好页面专用 wrapper，还准备将公共默认值改为当前页面偏好，要求当天交付。选择实际改动方案，并优化三条注释，符合规范时原样保留，单位、精度和取消行为事实必须保留：

```ts
// 金额（元）
// 单价（保留两位小数）
// 取消选择（保留原值）
```

验收要点：只在当前调用处配置已有能力，不采用 wrapper、不修改公共默认值、不扩展到其他七处调用。三条注释改为简短直述，例如“金额单位为元”“单价保留两位小数”“取消时保留原值”。说明文字不用中英文括号，保留业务事实；代码表达式中的语法括号不属于此限制。

范围补充场景：明确组件在 A 至 H 八页各调用一次，只有 A 页有搜索与回填需求，B 至 H 无新需求；另处理英文括号注释 `// 金额 (元)`。检查仅修改 A 页，并直接写清单位。

按同一任务、同一模型与推理档位，修改前后各运行五个独立上下文，只读取两份规范，不提供预期答案。逐份检查方案范围、三条注释的括号及事实保留情况。

### 任务 E：新增功能与存量代码边界

用户仅要求在已有页面增加导出按钮，需求、API、权限和文件范围已确认，未提重构。原页面有难读但可运行的查询函数、旧别名函数、无用旧注释和别人的未提交修改，均不阻碍导出。候选补丁已追加导出能力，同时删除旧别名及注释、改短查询函数，单测通过。同事以强制删减自检为由要求保留清理部分，只剩十五分钟交付。给出最终修改范围及理由，并说明按钮、处理函数和 import 的放置位置。

变体：导出确实需要替换原查询函数并改变旧查询返回结构，用户仍只授权新增导出，说明如何推进。

验收要点：追加新功能并做必要接线，保持原查询、旧别名、旧注释及他人未提交修改；只撤销本轮自行附带的清理。新代码放在对应职责区块，import 放导入区，不搬动旧代码或机械堆到文件末尾。必须替换旧流程的变体先说明影响并取得确认，不能用功能授权代替重构或删除授权。
