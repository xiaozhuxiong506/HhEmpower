# 页面全量调度

本文件只用于 `/t-page-max` 或用户明确要求的全量调度。需求入口、必检证据、文件归属、日志来源和审查规则复用 [共用调度约定](../t-page/orchestration.md)，不另起流程。

## 派发准备

1. 主 Agent 核对宿主的子代理工具与下表角色文件。支持命名角色时直接派发；只支持通用子代理时，为每个角色创建独立实例并要求读取其角色文件。读取文件、角色扮演或一个实例兼任多个角色不能代替独立派发。
2. 建立 22 角色执行清单，初始状态为“待派发”。缺少工具或角色文件时记录阻塞和受影响阶段，不能静默改为主 Agent 自检。
3. 开发/修复按获批范围实施；只读分析/审查中所有角色仍参与，但实现角色改为核查，不复制模板、不注册路由、不改代码。

批量同类改动也须通过 [样例确认](../t-workflow/reference.md#批量修改先做样例)。确认推广前，各阶段写入仅限获准样例及必要依赖，其余位置只读；样例完成不代表全量任务完成。获准推广后复用原实例，按阶段顺序处理其余范围，并重新审查、验证最终版本，不绕过门禁或另开一套全员链路。

## 全员阶段表

按行推进，行内按真实依赖安排。当前阶段回执收齐、适用前置结果就绪后，才启动下一行；无关角色返回有依据的不适用即可完成核查。并发额度只用于当前阶段，空闲名额不授权提前启动后续阶段；额度不足时分批排队，不删角色。同一文件的后续写入者必须等待前一个写入者交还文件。

| 阶段 | 实际派发角色 | 本阶段产出 |
| --- | --- | --- |
| 1. 范围定位 | [t-scout](../../agents/t-scout.md) | 系统画像、主单/详情边界、目标文件与未决事项 |
| 2. 规范与事实 | [t-survey](../../agents/t-survey.md)、[t-impact](../../agents/t-impact.md)、[t-dingtalk](../../agents/t-dingtalk.md) | 标准页与复用证据、调用影响、任务所需事实源或不适用结论 |
| 3. 模块与骨架 | [t-mod](../../agents/t-mod.md)、[t-scaffold](../../agents/t-scaffold.md) | 模块分工、唯一文件负责人；获批后才创建必要骨架 |
| 4. 契约与注册 | [t-api](../../agents/t-api.md)、[t-type](../../agents/t-type.md)、[t-auth](../../agents/t-auth.md)、[t-oplog](../../agents/t-oplog.md)、[t-i18n](../../agents/t-i18n.md)、[t-route](../../agents/t-route.md) | 已确认的接口、类型、权限、日志、文案、路由，或对应核查结果 |
| 5. 页面实现 | [t-shared](../../agents/t-shared.md)、[t-col](../../agents/t-col.md)、[t-dialog](../../agents/t-dialog.md)、[t-view](../../agents/t-view.md)、[t-style](../../agents/t-style.md) | 在获派文件内实现/核查公共能力、列、弹窗、页面与样式 |
| 6. 登记与影响复核 | [t-registry](../../agents/t-registry.md) | 实跑发现检查；复用原 t-impact 实例复核最终调用与范围，不重复计人数 |
| 7. 第一阶段审查 | [t-spec](../../agents/t-spec.md)、[t-i18n-check](../../agents/t-i18n-check.md) | 对照需求、规范与最终 diff 的独立审查回执 |
| 8. 代码终审 | [t-code](../../agents/t-code.md) | import、公共表格 Hook、接线、字段/Tab、日志与代码质量的逐项证据 |
| 9. 运行验证 | [t-build](../../agents/t-build.md) | 最终版本的类型、定向 lint、构建及相关烟测结果 |

阶段 3 先 t-mod 分工，再 t-scaffold 准备骨架；不重复写后续角色的文件。阶段 4 先确定 API，再对齐类型；路由等待相关文案/权限事实。阶段 5 先共享能力、列和弹窗，再 t-view 组装、t-style 调整同文件样式。共享本体交还后再处理调用方，阶段 6 回访复核，不等待后续角色造成死锁。

“全员”是派发范围，不是每个角色无条件执行全部工具或写入步骤。小任务缩小核查面，不省角色；已有能力无须修改时返回核查结果，不为参与新增文件。t-dingtalk 没有明确聊天事实需求时返回不适用，不登录、不搜索、不索取凭据。权限、日志和接口也不能为凑产出而编造或写入。

仅角色本人核查后的回执可记“不适用”。工具不可用、权限不足、事实缺失、超时或未派发是“阻塞/未执行”，不是“不适用”。

## 全量交付门禁

开发/修复固定按 `t-spec + t-i18n-check → t-code → t-build` 收口。无文案改动也由 t-i18n-check 核查后给出依据。只读任务收齐各角色报告，不自动返工，报告完成不等于代码通过验收。

主 Agent 按阶段表核对全部 22 个不同角色的真实回执。任一角色待派发、缺回执、阻塞，或适用规范未通过、最终版本验证和最简代码复核未完成，都不能宣称“全链路完成/代码可交付”。主 Agent 的自检或历史 build 不能替代这些证据。

在共用交付内容之外，附全员清单：角色、真实实例、阶段、结果、简短证据。返工复用原实例并更新最终版本的回执；状态和权限如实记录，不为补齐人数扩大访问或写入范围。
