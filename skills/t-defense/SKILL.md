# 防御性编程与边界校验（多语言通用）

只解决一个问题：**防御应该设在哪里**。静态类型只在编译期生效，外部流入的数据（网络、反序列化、文件、数据库、用户输入）完全不受类型保护。

## 与项目技能的分工

- TSB ERP 页面内的接口字段契约、归一化边界 → [t-standards](../t-standards/SKILL.md)，ERP 特化规则以其为准
- 本 skill 提供跨语言通用决策模型，适用于任意语言与任意项目

## 核心公理

1. **静态类型 ≠ 运行时保证** —— 编译期约束只覆盖源码内部；所有外部输入不受保护。
2. **可信域 vs 不可信边界** —— 可信域（内部调用，入参由本项目生成）信任类型系统，避免过度防御；不可信边界（外部流入）必须运行时校验。
3. **区分两类错误** —— 程序逻辑错误尽早崩溃、告警，不静默掩盖；外部输入错误要校验、记日志、可控拒绝或降级。
4. **过度防御的特征** —— 可信域内大量重复运行时校验、无脑兜底、捕获全部异常静默丢弃，掩盖缺陷并制造噪音。

## 通用决策总纲

1. 可信域：依赖静态能力（类型系统、编译检查、静态分析），不手写运行时类型校验。
2. 不可信边界：强制运行时校验；优先结构化校验库，不手写一堆 if。
3. 异常分层：IO/外部输入可捕获并记录、拒绝或降级；内部业务逻辑不捕获，让错误暴露。
4. 断言只校验内部不变量，严禁校验外部输入（生产环境断言会被关闭）。
5. 禁止捕获全部异常后静默返回兜底值。

## 不可信边界清单

HTTP 请求响应 · RPC 返回 · JSON/序列化反序列化 · 文件读取 · 配置解析 · 数据库查询结果 · 命令行参数 · 环境变量 · 第三方 SDK/回调 · 跨进程消息 · 用户输入。

## 通用踩坑清单

1. 把静态类型当运行时保护
2. 用断言校验外部输入（生产被禁用）
3. 防御位置搞反：内部疯狂判空，边界裸奔强转
4. 吞异常不记日志，线上无法定位
5. 零值陷阱：Go/Java/C# 反序列化缺失字段静默填零值/null

## 评审 Checklist

1. 当前代码属于可信域还是不可信边界？
2. 可信域：有没有多余的判空、类型判断、无脑兜底？
3. 不可信边界：是否用结构化校验库，而不是手写一堆 if？
4. 异常捕获是否只限 IO/外部边界；内部逻辑错误有没有被吞？
5. 错误分支是否记录日志；是否静默返回兜底值？
