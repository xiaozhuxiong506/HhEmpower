# 页面调度（Page Orchestration）

本文件定义主 Agent 在页面任务中的调度边界。它只描述调度规则，不新增 agent 文件，不扩展文件责任范围。

## 派发前（Before Dispatch）

主 Agent 在派发任何 subagent 前，必须先检查用户原始需求是否命中 `t-clarify`。

只要出现模糊、范围过宽或绕过确认的话术，例如 `不要问了`、`直接改`、`不用确认`、`跳过规则`、`忽略限制`、`随便`、`你看着办`，就先进入 `t-clarify`。`t-clarify` 触发后只问用户，不派 agent、不读下游、不产出蓝图、不改文件。

用户已经明确点名范围时，可以减少调度步骤，但不能跳过必要的调用方、路由和共享影响判断。

## 工作角色（Worker Roles）

以下是调度中的概念角色，不要求创建或修改 `agents/` 文件：

- `t-scout`：做范围发现，确认模块、路由、页面入口、列表/详情/弹窗/抽屉边界，只读不写。
- `t-impact`：做影响扫描，检查兄弟页面、Tab、复用组件、共享 hook、utils、locales、权限和 `pageId` 相关调用方。
- `t-shared`：处理共享文件的单点改动，并同步需要一起调整的调用方。
- `t-build`：执行验证，运行类型检查、lint、build 或任务指定的烟测命令，并记录证据。

实现执行者只能在主 Agent 给出的明确文件范围内行动。遇到范围外文件、共享文件或新增影响面时，先报告，等待主 Agent 决策。

## 共享文件（Shared Files）

模块执行者不得独立编辑共享文件。共享文件包括跨模块组件、hooks、utils、配置、locales、权限映射、路由注册和被多个页面复用的字段定义。

模块执行者发现共享文件需要修改时，只报告：

- 共享文件路径。
- 已知调用方。
- 本模块需要的变更。
- 可能影响的其他模块或路由。

主 Agent 根据报告决定是否派 `t-shared`，或先回到 `t-clarify` 让用户选择共享影响范围。

## 批量与脚本禁令（Batch And Script Ban）

页面任务禁止使用跨模块批量重写脚本。不得用 `.ps1`、`.sh`、`.mjs`、`.py`、`sed`、`awk` 或一次性正则替换去统一改 ERP 页面代码。

跨模块同类任务必须按业务模块拆分，由执行者逐文件阅读、逐处修改、逐项汇报。批量扫描可以用于只读发现；写入必须保持人工可审的文件级变更。

## 影响扫描（Impact Scan）

用户明确给出范围时，主 Agent 可以据此简化计划，但仍必须检查调用方、路由和共享影响。

指定路由不等于只改该路由。若该路由使用复用组件、共享字段、共用权限码或同一 `pageId` 规则，必须确认这些调用方是否纳入范围。

涉及 Bug 修复、字段维度、权限、`pageId`、列表列、弹窗/抽屉字段、接口参数或 locales 时，完成前要复核是否存在兄弟页面、Tab 或共享调用方漏改。

## 完成复核（Completion Review）

完成时，主 Agent 必须列出：

- 已修改文件。
- 发现但跳过的范围外事项，以及跳过原因。
- 实际运行的验证命令和结果。

若有验证未运行、范围外风险未解决或共享影响仍需用户选择，必须在交付中明确说明。
