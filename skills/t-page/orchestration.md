# 页面全员调度

本文件是 `t-page` 的执行约定。主 Agent 按阶段实际派发 `agents/` 中全部 22 个角色，逐一收取结果，再决定能否交付。角色的专业规范仍以各自文件和相关 Skill 为准。

## 执行模式

- 经 `t-page` 进入的 TSB 页面需求、开发、修复和审查均走全员链路；`t-start`、`t-new-module`、`t-review` 复用此入口。独立的钉钉/禅道查询及非页面任务不因此启动全员链路。
- 开发/修复模式：只实现已确认的需求及必要直接依赖，审查发现的本次缺陷交原负责人修正并复查。
- 只读分析/审查模式：所有角色仍参与，但实现角色改为只读核查，返回缺口或不适用，不复制模板、不注册路由、不改代码。审查发现问题时继续汇总各专业结论，不自动修复；“报告已完成”不等于“代码可交付”。
- “全员”不等于扩大需求或全仓扫描。小任务缩小输入和检查面，不能以简单、赶时间、已经 build 或主 Agent 已看过为由省掉角色、规范取证或审查。

## 派发前

1. 按 `t-page` 完成需求理解、画像探测和页面任务概览。未解决的范围、事实源、共享影响、权限或字段歧义交 `t-clarify`；已确认的信息直接沿用，不重复索要。澄清阻塞时只读已知事实，不派实现、不写代码。
2. 主 Agent 读取 `t-standards` 及 `reference.md`。涉及列表时加读 `t-list`；专业 Skill 按实际文件、调用关系和需求选择，不靠用户逐个点名。
3. 核对当前宿主的子代理工具与下表角色文件。支持命名角色时直接派发；只支持通用子代理时，为每个角色创建独立实例并要求读取其角色文件。读取角色文件、角色扮演和一次实例扮演多个角色不能代替独立派发。
4. 建立执行清单，初始状态均为“待派发”。若缺少子代理能力或角色文件，记录具体阻塞与受影响阶段；不能静默降级成主 Agent 自检并宣称全链路完成。

## 全员阶段表

按行推进，行内按真实依赖安排。当前阶段的回执收齐、适用前置结果就绪后，才启动下一行；无关角色返回有依据的不适用即可完成其核查。并发额度只用于当前阶段，空闲名额不授权提前启动后续阶段；额度不足时分批排队，不删减角色。先由 `t-scout` 确认范围，`t-survey`、`t-impact`、`t-dingtalk` 才接收其结果。同一文件的后续写入者必须等待前一个写入者交还文件。

| 阶段 | 实际派发角色 | 本阶段产出 |
| --- | --- | --- |
| 1. 范围定位 | [t-scout](../../agents/t-scout.md) | 系统画像、主单/详情边界、目标文件与未决事项 |
| 2. 规范与事实 | [t-survey](../../agents/t-survey.md)、[t-impact](../../agents/t-impact.md)、[t-dingtalk](../../agents/t-dingtalk.md) | 标准页与复用证据、调用影响、任务所需事实源或不适用结论 |
| 3. 模块与骨架 | [t-mod](../../agents/t-mod.md)、[t-scaffold](../../agents/t-scaffold.md) | 模块分工、唯一文件负责人；获批后才创建必要骨架 |
| 4. 契约与注册 | [t-api](../../agents/t-api.md)、[t-type](../../agents/t-type.md)、[t-auth](../../agents/t-auth.md)、[t-oplog](../../agents/t-oplog.md)、[t-i18n](../../agents/t-i18n.md)、[t-route](../../agents/t-route.md) | 已确认的接口、类型、权限、日志、文案、路由，或对应核查结果 |
| 5. 页面实现 | [t-shared](../../agents/t-shared.md)、[t-col](../../agents/t-col.md)、[t-dialog](../../agents/t-dialog.md)、[t-view](../../agents/t-view.md)、[t-style](../../agents/t-style.md) | 在获派文件内实现/核查公共能力、列、弹窗、页面与样式 |
| 6. 登记与影响复核 | [t-registry](../../agents/t-registry.md) | 实跑发现检查；复用原 `t-impact` 实例复核最终调用与范围，不重复计人数 |
| 7. 第一阶段审查 | [t-spec](../../agents/t-spec.md)、[t-i18n-check](../../agents/t-i18n-check.md) | 对照需求、规范与最终 diff 的独立审查回执 |
| 8. 代码终审 | [t-code](../../agents/t-code.md) | import、公共表格 Hook、接线、字段/Tab、日志与代码质量的逐项证据 |
| 9. 运行验证 | [t-build](../../agents/t-build.md) | 最终版本的类型、定向 lint、构建及相关烟测结果 |

阶段 3 的 `t-mod` 先给模块分工，`t-scaffold` 再准备骨架；它们不重复写后续专业角色的文件。阶段 4 先确定 API 契约，再对齐类型；路由等待相关文案/权限事实。阶段 5 先完成所需共享能力、列和弹窗，再由 `t-view` 组装，`t-style` 最后调整同文件样式。已有能力无需修改时，由该角色核查后返回，不为串联流程新增文件。

这是派发参与顺序，不是无条件执行角色的全部工具或写入步骤。`t-dingtalk` 没有明确的钉钉事实需求时，读取任务范围后返回“不适用”，不登录、不搜索聊天、不索取凭据。`t-oplog`、`t-auth` 等先判断本次是否涉及其职责，再按各自规则处理所需事实；不得为了让角色“干活”编造 pageId、权限码、接口或触发外部操作。

角色的默认触发描述用于普通独立调用；全员链路中即使未命中关键词也须派发进行适用性核查。仅角色本人核查后的回执可记“不适用”。工具不可用、权限不足、缺少事实、超时或未派发是“阻塞/未执行”，不是“不适用”。

## 单一调度与文件归属

- 由主 Agent 统一创建、排队、等待和复用实例。`t-mod`、`t-scaffold` 或其他角色需要下游工作时返回任务与文件清单，不自行再开一套子代理，避免重复派发。各角色收到任务后只执行获派职责，不再次运行整个 `t-page`。
- 每个角色独立读取其角色文件、命中的 Skill 和必要参考，回执列出实际读取项。只读 description、列一个 Skill 名或收到主 Agent 的摘要不等于完成规范读取。
- 每个可写文件在同一时刻只有一个负责人。`index.vue` 由 `t-view` 组装，再交 `t-style`；弹窗内部交 `t-dialog`，父页接线交 `t-view`；`t-col` 只管列定义，不代写页面逻辑。
- 公共组件、Hook、通用 utils 实现由 `t-shared` 单点修改。具有独立职责的登记文件仍归专项角色：API 归 `t-api`、类型归 `t-type`、auth 归 `t-auth`、operationLog 归 `t-oplog`、locales 归 `t-i18n`、路由归 `t-route`。共享属性不豁免用户确认与引用扫描，专项角色与 `t-shared` 不得争写。
- 调用既有公共 Hook 不等于修改 Hook 本体。新增公共层、依赖、文件或跨模块修改仍执行 `anchors.md` 与 `t-standards` 的确认和最小改动要求。
- 子代理不得顺手修改范围外问题。跨模块任务按模块锁定文件，仍禁止脚本批量改 ERP 业务源码。

## 派发输入与角色回执

主 Agent 给每个角色传入以下信息；首次只读核查不授予写权限，实施前再明确可写文件：

```text
角色及角色文件：<名称、当前插件内实际路径>
任务模式：开发/修复 或 只读分析/审查
阶段与前置结果：<已完成角色回执、尚未解决的阻塞>
用户需求与确认：<正向目标、范围、验收标准；不包含自行扩展>
系统画像与证据：<已确认系统、业务源码根/路由；沿用本任务结论，不从后台 URL 或共享组件重新猜测>
可读范围 / 可写文件：<明确路径；无写入授权时写“无”>
规范与事实：<标准页、规范参考、接口/权限/字段事实、必要 Skill 路径>
本角色交付：<实现/核查内容与证据；无关时本人核查后说明不适用>
调度边界：只执行本角色；不自行派发其他角色；不扩大外部访问。
```

每个实际实例至少有一条回执，由主 Agent 补入工具返回的真实实例标识：

涉及日志的 `t-oplog` 派发与回执还须带上 [日志目标与来源核对](../t-oplog/SKILL.md#日志目标与来源核对) 中的系统、后台应用、PC 平台及逐项 pageId 来源。主 Agent 将同一份证据交给 `t-code` 复核；来源缺失或系统冲突时停在日志步骤，不换用其他系统结果。多个角色使用后台时，应用切换与保存不得并发操作同一标签页。

| 角色 / 实例 | 阶段 | 实际读取的规范 | 文件或检查范围 | 证据 | 结果 |
| --- | --- | --- | --- | --- | --- |
| <角色 / 工具返回标识> | <阶段> | <实际读取路径> | <路径或明确无写入> | <代码位置、检查命令及结果或不适用依据> | 通过 / 不适用 / 需修正 / 阻塞 |

“待派发”“执行中”只表示进度，不是完成回执。角色已经派发但尚未返回时不能先记通过。同一角色返工可复用实例，但必须更新其负责的最终文件版本和复查结果。跨模块的多个 `t-mod` 实例分别记录，不代替其他角色。

## 实现前必检证据

`t-survey` 必须在写入开始前给出下表的标准来源；对应实现者按来源实现，`t-code` 对最终源码独立复核。三个槽位每次都必须有结论；确实不涉及的项写明范围依据，不以空值或“同标准”代替。

| 必检项 | 写入前的标准证据 | 实现与终审证据 |
| --- | --- | --- |
| import | 当前画像标准页的实际 import 组、`t-standards/reference.md` 的 import 顺序、相关 lint 配置 | 本次文件的 import 位置与对照结果；不能拿 legacy 旧页作新页标准 |
| 公共表格 Hook | 实际 Hook 导出/来源、标准页调用、项目列偏好 API 与保存链路 | 列表核查 `useGridPreferences`、`useColWidthSave`、恢复/提交偏好、`resizable-change` 等实际接线，不能只检查两个 import 名称 |
| 现成能力复用 | 本次所需 utils、hooks、directives、fieldMapping/filedMapping 的实际导出与适配依据 | 实际调用位置；没有或不适配时记录搜索范围和理由，不为补表造公共抽象 |

列表基线以 [t-list](../t-list/SKILL.md) 和当前项目标准源码为准；列偏好已有公共 Hook/API 时不能用页面 localStorage 或手写监听替代。非列表组件不强塞列表 Hook，但新建或改动的 grid 仍按命中的规范核对虚拟滚动、height、列宽与字段设置。

标准文件、Hook 导出或事实源找不到时先报告缺口，不能填写猜测路径或复制旧实现冒充取证。其他权限、日志、i18n、字段、Tab 和防御性编程规范由相关角色按实际范围覆盖，以上三项不替代专业检查。

## 审查、返工与验证

开发/修复模式按 `t-spec` 与 `t-i18n-check` → `t-code` → `t-build` 的顺序收口。第一阶段未通过先修正并复查，再进入代码终审；代码终审未通过先回原实现者，不能先跑 build 来抵消审查结论。用户仅要求只读审查时仍收齐各角色报告，明确失败项，不进入返工。

- `t-spec` 对照需求、范围、规范取证与 diff；`t-i18n-check` 对照实际文案；`t-code` 给出上述三个必检槽位及相关专业项的结论。无 i18n 变更也由 `t-i18n-check` 本人核查当前涉及文案后返回，不由主 Agent 预先删掉此角色。
- 违反本次适用规范的 Critical 或 Warning 都需要修正，不能因严重级别较低自动放行；一般建议与范围外既有问题只报告，不擅自扩大改动。用户明确接受某项偏离时记录具体项与影响，交付不得标“规范全部通过”。
- 修正后把实际 diff 交原审查者复查；改动影响前一阶段结论时使其失效并补查。运行验证之后又修改源码，旧验证不能覆盖新版本，重新执行受影响的审查和验证。
- `t-build` 先检查包管理器、项目脚本和副作用，再运行既有类型检查、仅本次文件的 lint、开发交付所需构建和相关烟测。不得使用 `--fix`、运行发布脚本、修改依赖，或用浏览器操作生产写接口。只读任务遵守用户限制，不能安全执行的检查明确记“未运行”。
- 每个验证项记录命令、范围、退出结果和验证版本；历史错误与本次新增错误分开。未配置、无法运行或未授权的检查记录缺口，不伪造通过。
- 连续三轮核心问题未解决时停止重复同一路径，重新核对需求、事实源和失败证据，报告阻塞与下一步；不无限重试或扩大范围。

## 交付门禁

主 Agent 按阶段表核对全部 22 个不同角色的真实回执。任一角色待派发、无回执、阻塞，或适用规范未通过、最终版本验证未完成、最简代码复核未完成，都不能宣称“全链路完成/代码可交付”。用户范围与宿主权限始终限制执行，不能为补齐人数绕过。

最简代码复核在交付前由主 Agent 按最终 diff 执行：逐文件核对“删掉后功能仍正确”的代码已删除，无需求外新增文件、抽象、依赖、注释和防御；判定标准用 [t-workflow#复杂度预算与最简代码](../t-workflow/SKILL.md#复杂度预算与最简代码必守) 的删减自检清单。角色审查通过不代替删减复核；各角色也不为体现产出而追加需求外代码、注释或防御。

最终输出：

1. 已实现内容或只读审查结论，以及实际修改文件。
2. 全员执行清单：角色、真实实例、阶段、结果、简短证据；同角色返工记录最新结论。
3. import、公共表格 Hook、现成能力复用三项必检结果，以及规范/文案审查、代码终审和运行验证结果。
4. 最简代码复核结论：已删除项与保留理由；存在更简单方案能同样满足需求时不得交付。
5. 未运行检查、待确认事实、接受的偏离及范围外发现。可以交付未完成状态说明或只读报告，不能把它们写成“全部通过”。

清理本次临时接口 dump 等取证产物，不生成无关追踪文件。回执和阶段清单默认留在对话中。单入口的调用不授权 Git 提交、推送或发布。

维护本调度约定时，用 [行为测试场景](../../tests/t-page-orchestration.md) 验证实际决策，不以匹配文档关键词代替测试。
